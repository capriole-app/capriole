# ADR 0008 — Interfaccia: Svelte 5 per la web app, Tauri per il desktop

Data: 2026-10-01 · Stato: **accettata** (decisione dell'utente)

## Contesto

La fase 8 porta le prime funzioni all'utente, e con esse l'interfaccia. La specifica (CAPRIOLE.md §3)
vuole una web app tutta nel browser (il motore WASM in un Worker, i file non escono dal dispositivo) e
un'app desktop con lo stesso codice; l'API C (ADR 0001) lascia libera la scelta. Nel workspace le app
web usano già Svelte 5 (runes) con SvelteKit statico, Tailwind 4 e i componenti shadcn-svelte —
l'Inspector di Capriole compreso (standard frontend del workspace).

## Decisione

- **Web app: Svelte 5** in modalità runes, **SvelteKit 2 statico** (adapter-static, nessun server),
  Vite, Tailwind 4: lo stack dell'Inspector e degli altri progetti. Nuova app `apps/capriole`.
- **Desktop: Tauri** (`apps/desktop`): la stessa web app in una webview, con aperture e salvataggi
  nativi; il motore resta il modulo WASM (lo stesso codice del sito), l'FFI verso il motore nativo
  resta possibile attraverso l'API C. Linux di prima classe, distribuzione Flathub.
- Il codice che parla col motore (worker, client, tipi del JSON) esce dall'Inspector in un pacchetto
  condiviso, `packages/engine-client`, usato da entrambe le app.

## Conseguenze

- Una sola UI per web e desktop; le funzioni che il browser non permette (smart card, OCSP/CRL senza
  CORS: CAPRIOLE.md §6.1) passano per comandi Tauri dell'app desktop.
- Tauri richiede la toolchain Rust e WebKitGTK (librerie di sviluppo) sulla macchina di build: si
  installano quando si arriva al passo 8c (PLAN.md).
